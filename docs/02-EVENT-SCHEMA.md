# 02 — Event Schema (THE CONTRACT)

This is the **single source of truth** shared by `server.py`/`orchestrator.py` (producers) and `web/src/lib/eventStore.js` (consumer). Backend and frontend agents MUST implement exactly this. If you change it, change it here first.

## Transport
- SSE. Each event is one `data:` line containing a JSON object, terminated by `\n\n`.
- Every event has: `type` (string), `ts` (ISO 8601 string, server-stamped), and a `payload` object.
- The stream ends with a `done` event; server then closes the connection.

```
data: {"type":"score_update","ts":"2026-06-27T15:02:11Z","payload":{"phase":"before","value":48}}

```

## Event types

| `type` | When | `payload` fields |
|---|---|---|
| `run_started` | run begins | `{ run_id, job_title?, company? }` |
| `skill_loaded` | once per skill at startup | `{ name, description, model }` |
| `plan` | orchestrator finishes planning | `{ todos: [{id, title, status}] }` (status: `pending`) |
| `todo_update` | a todo changes state | `{ id, status }` (status: `pending`\|`in_progress`\|`done`) |
| `subagent_start` | a subagent begins | `{ name }` |
| `subagent_finish` | a subagent ends ok | `{ name, summary? }` |
| `subagent_error` | a subagent failed | `{ name, error }` |
| `score_update` | ATS score computed | `{ phase: "before"\|"after", value: 0-100, missing_keywords?: string[], matched_keywords?: string[] }` |
| `deliverable` | an output is ready | `{ kind, title, content_markdown }` |
| `token_usage` | periodic cost meter | `{ input_tokens, output_tokens, est_cost_usd, by_model?: {model: tokens} }` |
| `log` | human-readable activity line | `{ level: "info"\|"warn"\|"error", message }` |
| `done` | run finished | `{ before, after, deliverable_kinds: string[], elapsed_s }` |

### `deliverable.kind` enum
`"company_research"` · `"tailored_resume"` · `"cover_letter"` · `"interview_prep"`

### Notes
- `content_markdown` is rendered as Markdown in the UI (sanitize before injecting HTML).
- `score_update` with `phase:"before"` should arrive early; `phase:"after"` near the end. The UI animates the dial from before→after.
- `missing_keywords` on the "before" event drives the red→green keyword highlighting.
- `token_usage` may be emitted a few times; UI shows the latest.

## Minimal producer helper (backend)
```python
# agent/events.py
import json, datetime
def ev(type_, **payload):
    return {"type": type_, "ts": datetime.datetime.utcnow().isoformat()+"Z", "payload": payload}
def sse(event: dict) -> str:
    return f"data: {json.dumps(event)}\n\n"
```

## Minimal consumer (frontend, Svelte store)
```js
// web/src/lib/eventStore.js
import { writable } from 'svelte/store';
export const state = writable({
  todos: [], skills: [], activeAgents: new Set(),
  scoreBefore: null, scoreAfter: null, missingKeywords: [],
  deliverables: {}, log: [], usage: null, done: false,
});
export function connect(runId) {
  const es = new EventSource(`http://localhost:8000/events/${runId}`);
  es.onmessage = (e) => apply(JSON.parse(e.data));
  return () => es.close();
}
function apply(evt) { /* switch(evt.type) → state.update(...) ; close on 'done' */ }
```

## trace.json (mock mode)
- An **array of events** in the SAME schema, in fire order.
- Add a synthetic `delay_ms` field per event (UI-only) so replay paces realistically; the live path ignores it.
- Generated by recording one real run (see `07` task M). The UI's mock mode reads `trace.json` and dispatches events on their `delay_ms` timeline — zero network.
